## 3. ADI / Neighborhood Atlas — registration required, and it is the best-vintaged Block B source

> **EXPANDED 2026-08-26** with the full registration process, the available vintages,
> the suppression coding, and a **grain conflict that changes Task 2.5**.

`https://www.neighborhoodatlas.medicine.wisc.edu/`

### 3.1 What ADI is, and what it is doing in this analysis

The Area Deprivation Index ranks neighbourhoods on income, education, employment, and
housing quality, at **census block group** level, validated to that grain by Kind et al.
(*Ann Intern Med* 2014;161(11):765–74). Current methodology is **v4.0.1**, which adds a
shrinkage step to stabilise block-group component estimates against ACS sampling noise.

Two distributions are published:
- **national percentile 1–100** (1 = least disadvantaged, 100 = most)
- **state decile 1–10**, ranked within each state alone

**Use the national percentile.** State deciles are ranked within state, so they are not
comparable across the 51-state frame and would silently absorb state effects.

**Its job here** is not to duplicate SVI. It is (a) the only disadvantage measure whose
vintage actually covers the outcome period (§3.2), (b) a second, independently
constructed measure of the same latent construct, which is what makes the Rashomon
width story meaningful — if ADI and SVI disagree about which hospitals serve
disadvantaged catchments, that disagreement *is* specification uncertainty, and (c) the
finest grain available, at block group rather than tract.

### 3.2 Vintages, and the one that matters

From the Atlas changelog (last updated 2026-07-01), the {YYYY} ADI is built on the
ACS {YYYY−4}–{YYYY} 5-year estimates. Currently available:

| Vintage | ACS basis | Data midpoint | **Gap to PSI midpoint (2023-07-01)** |
|---|---|---|---|
| **2024** (v4 methodology) | ACS 2020–2024 | 2022-07-01 | **1.0 year** |
| 2020 (updated to v4) | ACS 2016–2020 | 2018-07-01 | 5.0 years |
| 2015 (updated to v4) | ACS 2011–2015 | 2013-07-01 | 10.0 years |

**Take the 2024 vintage.** At a 1.0-year gap it is *three times better aligned than
SVI 2022*, whose gap is 3.0 years (§4) and for which no newer release exists — I probed;
SVI 2023 and 2024 both return 404.

This materially raises ADI's importance above what `plan-amendments.md` assumed. It is
not merely a nice-to-have second construction: **it is the only Block B disadvantage
measure that describes the communities during the period the PSI events occurred.** SVI
describes them as of roughly 2020, spanning the pandemic's economic disruption.

Keep **ADI 2020 as a specification-space axis** alongside 2024 — it is a free vintage
sensitivity on the covariate the headline claim rests on.

### 3.3 The grain conflict — this changes Task 2.5

The Atlas is explicit, and it is aimed squarely at what a naive catchment build would do:

> The ADI should not be used at any levels other than the core Census geographies for
> which it is validated, specifically the Census block group.

It **does not publish** a 5-digit ZIP or ZCTA dataset, deliberately, citing precision
loss where "concentrated poverty abuts more wealthy regions" (Kind et al., *Health
Affairs*, 2016). It publishes instead a **9-digit ZIP (ZIP+4) crosswalk** built to
correspond directly to block groups.

**The problem:** the Hospital Service Area File gives **5-digit ZIP only**. The ZIP+4
crosswalk cannot be used, and the ZCTA route is the one the Atlas warns against.

**The resolution, committed here:** aggregate block-group ADI to **census tract** by
population weighting, then apply the existing ZCTA→tract catchment machinery. This is
defensible in a way the ZCTA route is not, because **block groups nest exactly within
tracts** — the aggregation is an exact hierarchical roll-up with no allocation error,
and tract is itself a core Census geography. The only allocation step is ZCTA→tract,
which SVI already requires, so ADI adds no new source of error beyond what the design
already carries.

Three things must be stated in report §3 rather than left implicit:
1. ADI is aggregated from block group to tract by population weighting before catchment
   weighting, and the Atlas's ZCTA warning is therefore not violated.
2. Averaging a **percentile rank** across block groups is a rank-of-ranks. It is standard
   and acceptable, but it is not the same object as a block-group ADI and should not be
   described as one.
3. The block-group-to-tract aggregation loses within-tract heterogeneity, which is
   exactly the granularity ADI was chosen for. **That is a real cost of the ZIP-based
   catchment design and it belongs in Limitations**, alongside the note that the HCUP
   path — patient-level data with finer geography — is what would remove it.

### 3.4 Registration: **self-service, not a review process**

I had this wrong in the first draft of this note, where I flagged it as a turnaround
risk. It is not. There is no application, no committee, no DUA, and no institutional
sign-off. Per the Atlas: *"ADI rankings are free and available to the public, but we ask
that you create a login with our system to download them."*

**Process, in full:**

1. Go to `https://www.neighborhoodatlas.medicine.wisc.edu/` and use **"Create an
   Account"** on the home page. (The bare `/register` path 404s — use the home-page
   form.)
2. Supply name, email, institutional affiliation (JHF), and intended use. A one-line
   purpose is sufficient: *hospital-level analysis of patient-safety indicator variance
   against community disadvantage.*
3. **A confirmation email arrives; the email address must be validated.** The Atlas's
   own FAQ warns this mail frequently lands in spam — check there before assuming
   failure.
4. Log in at `/download` and take:
   - **2024 ADI, national, census block group level** — the primary file
   - **2020 ADI, block group** — for the vintage axis
   - the block-group geography/crosswalk file if offered alongside
   - *not* the ZIP+4 crosswalk; it cannot be joined to 5-digit HSAF ZIPs

**Known failure modes, from the Atlas FAQ:** if the validation email does not arrive,
request a new one rather than re-registering; if login fails after validation, switch
browsers — the Atlas states Chrome and Firefox work best and that switching between
them sometimes resolves it.

**Realistic turnaround: minutes to a few hours**, bounded by email delivery. Record the
actual dates anyway, because Task 0.4 asks for the turnaround by name and because a
future reader of the provenance table needs to know access was trivially obtainable.

**Why I cannot do this step.** Creating an account under Carl's name and affiliation,
and agreeing to the Atlas's Terms of Use on his behalf, is his action, not mine.
Everything downstream of the download is mine.

### 3.5 Parse traps, recorded before the file is opened

The ADI value column is **character, not numeric** — it carries suppression codes inline,
the same class of trap as HSAF's `*` and the Care Compare footnotes.
**Corrected 2026-08-27 against the delivered files:** the combined code is `GQ-PH`,
not `PH-GQ` as first recorded here. Verified in both vintages by `R/acquire-adi.R`.

| Code | Meaning | Handling |
|---|---|---|
| `PH` | fewer than 100 people and/or fewer than 30 housing units | genuinely missing; do not impute |
| `GQ` | more than 33% of population in group quarters | missing, and **non-random** — prisons, dorms, nursing homes; enumerate them |
| `GQ-PH` | both | missing |
| `QDI` | Questionable Data Integrity, from missing ACS source data | missing |

`GQ` suppression is the one to watch: it removes institutional populations, which are
neither randomly distributed nor irrelevant to a hospital's catchment. The count of
`GQ`-suppressed block groups falling inside each hospital's catchment should be
recorded, exactly as `catch_coverage` is.

### Geographic grain — a decision Phase 2 must make

SVI's primary file is **census-tract** level; the Service Area File is **ZIP** level.
Catchment weighting therefore needs one of:

- **(a) ZIP → county, using the SVI county file.** One crosswalk, coarse but clean,
  and it aligns with AHRF, CHR, and RUCC which are all county-level anyway.
- **(b) ZIP → tract, using the HUD USPS crosswalk** (`huduser.gov/portal/datasets/usps_crosswalk.html`,
  reachable), preserving tract granularity at the cost of an allocation step that
  introduces its own error.

> **RECOMMENDATION WITHDRAWN 2026-08-26.** I measured it. At **county** grain the
> catchment-weighted SVI correlates **0.89–0.97** with the naive hospital-county value,
> and imputing the suppressed cells moves that by only ~0.01 — so the redundancy is not
> a suppression artifact, it is the grain. County-grain catchment weighting buys about
> three correlation points for eight hours. **The base case moves to (b), ZIP→tract**,
> with county as the documented fallback for the 130 gate-B0.a hospitals. Evidence and
> revised task hours: `plan-amendments.md` §2.2 and §2.4.
>
> Also: **the HUD crosswalk now requires an API token** and is dropped. The **Census
> 2020 ZCTA relationship files** are free, need no token, and were verified working
> (ZCTA→county, 33,791 entries). That removes a registration dependency from Phase 1.
